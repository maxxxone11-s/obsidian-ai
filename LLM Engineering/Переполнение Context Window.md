# Переполнение Context Window

## Академическое определение

Переполнение Context Window — ситуация, при которой суммарный объём входного контекста и потенциального ответа превышает максимальное количество токенов, поддерживаемое моделью.

## Инженерное назначение

Контроль переполнения требует от backend заранее рассчитывать размер запроса и применять стратегию сокращения контекста до обращения к модели.

## Причина существования

API не знает, какие части контекста можно удалить без потери смысла задачи. Такое решение зависит от логики приложения и поэтому остаётся ответственностью backend.

## Простое объяснение

Если запрос вместе с будущим ответом не помещается в окно контекста, модель обычно не начинает генерацию, а API возвращает ошибку.

## Как это работает

1. Backend выполняет [[Token Counting]].
2. Складывает входные токены и зарезервированные output tokens.
3. Сравнивает сумму с [[Context Window]].
4. При превышении создаёт summary, удаляет неактуальную историю, уменьшает объём RAG-контекста или снижает `max_tokens`.
5. После повторной проверки отправляет запрос.

## Пример

```text
History:   90 000
RAG:       25 000
User:       7 500
max_tokens: 3 000
Итого:    125 500
```

Если лимит модели равен 128 000, запрос помещается; если дополнительные инструкции увеличат вход более чем на 2 500 токенов, возникнет переполнение.

## Типичные ошибки

- Ожидать, что API автоматически удалит лишнюю информацию.
- Проверять только входной контекст и забывать про `max_tokens`.
- Не рассчитывать размер запроса заранее.

# Messages как источник контекста модели

Область: [[LLM Engineering/LLM Engineering|LLM Engineering]]

## Академическое определение

Массив `messages` представляет собой полный контекст, который получает модель при каждом API-запросе.

## Инженерное назначение

`messages` позволяет передавать историю диалога, инструкции и дополнительные данные без хранения состояния внутри модели.

Backend отвечает за сборку контекста и за то, какие сообщения попадут в текущий запрос.

## Причина существования

LLM не обладает долговременной памятью между API-запросами.

Поэтому весь необходимый контекст должен быть отправлен повторно.

## Простое объяснение

Backend самостоятельно хранит историю сообщений и при каждом запросе заново формирует массив `messages`.

Модель видит только то, что находится в текущем массиве.

## Как это работает

```text
Backend
    ↓
История сообщений
    ↓
messages[]
    ↓
LLM
```

## Пример

```python
messages = [
    {"role": "system", "content": "..."},
    {"role": "user", "content": "..."},
    {"role": "assistant", "content": "..."},
    {"role": "user", "content": "..."},
]
```

## Типичные ошибки

- Ожидать, что модель сама помнит предыдущие запросы.
- Отправлять только последнее сообщение, теряя необходимый контекст.
- Нарушать логический порядок сообщений.
- Путать память приложения с памятью модели.

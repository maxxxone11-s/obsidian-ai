# Prompt Caching

## Академическое определение

Prompt Caching — поддерживаемый LLM-провайдером механизм повторного использования вычислений для неизменяемого префикса prompt, уменьшающий задержку и, если это предусмотрено тарифом, стоимость повторных запросов.

## Инженерное назначение

Механизм позволяет многократно использовать уже обработанные большие инструкции или другой стабильный префикс без полного повторения вычислений.

## Причина существования

Большие system prompts и общие документы часто одинаковы в тысячах запросов. Повторное вычисление одного префикса расходует время и ресурсы.

## Простое объяснение

Провайдер повторно использует обработанную неизменяемую часть входа. Это не cache готового ответа.

## Как это работает

1. Первый запрос содержит стабильный префикс prompt.
2. Провайдер обрабатывает его и сохраняет пригодное для повторного использования состояние.
3. Следующий запрос с совпадающим префиксом получает cache hit.
4. Изменяемая часть запроса обрабатывается как обычно.

Конкретные условия, срок жизни и тарификация зависят от провайдера.

## Пример

System prompt занимает 12 000 токенов и остаётся неизменным, а user prompt меняется. Провайдер может повторно использовать обработку стабильного префикса.

## Типичные ошибки

- Путать Prompt Caching с Redis или cache готовых ответов.
- Думать, что Prompt Cache хранит окончательные ответы модели.
- Считать, что механизм полностью реализуется backend независимо от провайдера.
- Игнорировать требования провайдера к совпадению префикса.

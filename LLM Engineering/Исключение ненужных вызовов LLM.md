# Исключение ненужных вызовов LLM

Область: [[LLM Engineering/LLM Engineering|LLM Engineering]]

## Академическое определение

Исключение ненужных вызовов LLM — стратегия маршрутизации, при которой backend сначала пытается обработать запрос детерминированной программной логикой и обращается к модели только при необходимости.

## Инженерное назначение

Стратегия полностью исключает стоимость и задержку LLM для задач, не требующих генерации, понимания неоднозначного языка или сложного рассуждения.

## Причина существования

Часть запросов можно надёжнее и дешевле обработать бизнес-логикой, шаблоном, поиском в cache или обычной функцией.

## Простое объяснение

Перед вызовом модели backend проверяет, нельзя ли решить задачу обычным кодом.

## Как это работает

```text
User → Backend → Простая детерминированная задача?
                    ├── Да → Ответ без LLM
                    └── Нет → LLM
```

Правила обхода должны быть наблюдаемыми и не перехватывать запросы, для которых действительно нужна модель.

## Пример

На сообщение «Спасибо» backend может вернуть заранее определённое «Пожалуйста!» без обращения к LLM.

## Типичные ошибки

- Отправлять абсолютно все сообщения в LLM.
- Использовать модель для задач, которые проще решить Python-кодом.
- Создавать слишком широкие правила, ошибочно обходящие LLM для сложных запросов.

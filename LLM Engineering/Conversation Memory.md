# Conversation Memory

## Академическое определение

Conversation Memory — механизм хранения и повторной передачи истории диалога приложением, благодаря которому LLM учитывает предыдущие сообщения, несмотря на отсутствие собственной долговременной памяти между API-запросами.

## Инженерное назначение

Механизм позволяет поддерживать связный многошаговый диалог без хранения состояния внутри модели.

## Причина существования

Каждый обычный API-запрос к LLM независим. Чтобы модель учитывала прошлые реплики, приложение должно сохранить и снова передать необходимую историю.

## Простое объяснение

Помнит не модель, а backend: перед каждым запросом он заново формирует нужную часть разговора.

## Как это работает

1. Backend сохраняет сообщения пользователя и модели.
2. При новом сообщении загружает историю сессии.
3. Добавляет новую реплику.
4. С учётом [[Memory Management]] выбирает нужный фрагмент истории.
5. Передаёт сформированный `messages` в LLM.

## Пример

```text
User: Привет
Assistant: Привет!
User: Как тебя зовут?
```

Для ответа на третий message backend повторно передаёт модели предыдущие сообщения либо их достаточное резюме.

## Типичные ошибки

- Считать, что модель хранит память между API-запросами.
- Передавать модели только последнее сообщение пользователя.
- Без ограничений пересылать всю историю диалога.

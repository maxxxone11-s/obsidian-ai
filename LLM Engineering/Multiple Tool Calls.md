# Multiple Tool Calls

Область: [[LLM Engineering/LLM Engineering|LLM Engineering]]

## Академическое определение

Multiple Tool Calls — возможность LLM сформировать несколько запросов на вызов инструментов в рамках одного ответа, после чего backend определяет порядок и стратегию их выполнения.

## Инженерное назначение

Механизм позволяет эффективно получить несколько независимых результатов без дополнительных обращений к модели для выбора каждого инструмента.

## Причина существования

Пользовательские задачи часто требуют нескольких независимых операций. Их последовательный выбор через отдельные LLM-запросы увеличивал бы задержку и стоимость.

## Простое объяснение

Модель определяет, какие инструменты нужны, а backend решает, выполнять их последовательно или параллельно.

## Как это работает

1. LLM возвращает несколько tool calls.
2. Backend анализирует зависимости между ними.
3. Независимые вызовы можно выполнить параллельно, зависимые — последовательно.
4. Все результаты возвращаются модели для следующего шага [[Tool Loop]].

## Пример

```text
Запрос: сравнить погоду в Paris, London и Berlin
LLM: три вызова get_weather(...)
Backend: параллельно выполняет независимые HTTP-запросы
```

## Типичные ошибки

- Считать, что LLM самостоятельно определяет фактическую параллельность выполнения.
- Выполнять зависимые функции одновременно.
- Не учитывать ограничения и зависимости инструментов.

# Memory Management

Область: [[LLM Engineering/LLM Engineering|LLM Engineering]]

## Академическое определение

Memory Management — процесс отбора, хранения, обновления и передачи модели релевантной информации, позволяющий эффективно использовать ограниченное Context Window.

## Инженерное назначение

Управление памятью сохраняет качество ответов в длительных диалогах, одновременно контролируя размер контекста, задержку и стоимость запросов.

## Причина существования

Полная история со временем перестаёт помещаться в Context Window и накапливает нерелевантные данные. Backend должен решать, что сохранить, сжать, извлечь или исключить.

## Простое объяснение

Memory Management отвечает на вопрос: «Что именно нужно отправить модели в следующий запрос?»

## Как это работает

1. Приложение получает новое сообщение.
2. Определяет сведения, необходимые для текущей задачи.
3. Выбирает стратегию: sliding window, summary memory, semantic memory или retrieval.
4. Собирает релевантный контекст из [[Conversation State]].
5. Проверяет размер через [[Token Counting]].
6. Передаёт подготовленный контекст модели.

## Пример

В длинной сессии backend может сохранить краткое summary старых сообщений, добавить последние десять реплик и извлечь из долговременного хранилища только факты, относящиеся к текущему вопросу.

## Типичные ошибки

- Передавать модели всю доступную информацию.
- Путать объём памяти с качеством памяти.
- Не отделять важную информацию от второстепенной.
- Смешивать память приложения с внутренним состоянием модели.

# Tool Loop

## Академическое определение

Tool Loop — управляемый приложением цикл взаимодействия между LLM, backend и инструментами, в котором модель запрашивает вызовы, получает результаты и использует их для продолжения работы или окончательного ответа.

## Инженерное назначение

Цикл объединяет рассуждение модели и выполнение внешних действий в единый контролируемый workflow.

## Причина существования

Один запрос может требовать нескольких обращений к модели и инструментам. Одного ответа LLM недостаточно, когда для решения нужны внешние данные или действия.

## Простое объяснение

Обычно модель вызывается как минимум дважды: сначала для выбора инструмента, затем для ответа по результату инструмента.

## Как это работает

1. Backend отправляет запрос модели.
2. Модель возвращает tool call.
3. Backend валидирует и выполняет вызов.
4. Backend добавляет tool result в историю сообщений.
5. Модель либо запрашивает следующий инструмент, либо формирует final answer.

## Пример

```text
User → LLM → get_weather() → Backend → Weather API
     ← окончательный ответ ← LLM ← tool result
```

## Типичные ошибки

- Считать, что LLM вызывается только один раз.
- Передавать сырой результат функции пользователю без повторного обращения к LLM.
- Думать, что циклом выполнения управляет модель, а не backend.

# Retrieval-Augmented Generation (RAG)

## Академическое определение

Retrieval-Augmented Generation — архитектурный подход, при котором система перед генерацией ответа извлекает релевантную информацию из внешнего источника знаний и передаёт её языковой модели как контекст.

## Инженерное назначение

RAG позволяет использовать актуальные, приватные и большие базы знаний без изменения параметров языковой модели и связывать ответы с внешними источниками.

## Причина существования

LLM хранит знания в параметрах, а не в доступной базе данных, и не умеет самостоятельно обращаться к новым документам. Внешний retrieval-этап приносит нужные данные во время запроса.

## Простое объяснение

Система работает как студент с книгой: сначала находит подходящий фрагмент, затем формулирует ответ на его основе, вместо попытки помнить всё заранее.

## Как это работает

1. Пользователь задаёт вопрос.
2. Retriever ищет релевантные [[RAG/Chunk|фрагменты]] во внешней базе знаний.
3. Найденный контекст добавляется к prompt.
4. LLM генерирует ответ на основе вопроса и найденных данных.

## Пример

Пользователь задаёт вопрос по внутреннему PDF компании. Retriever находит релевантные фрагменты, а LLM получает их вместе с вопросом и формирует ответ.

```python
query = "Что такое RAG?"
documents = retriever.search(query)
prompt = f"На основе документов: {documents}\nОтветь на вопрос: {query}"
answer = llm.generate(prompt)
```

## Типичные ошибки

- Считать, что RAG обновляет знания или параметры модели.
- Путать RAG с Fine-tuning.
- Думать, что LLM самостоятельно ищет информацию в документах.
- Передавать модели шумные или нерелевантные документы.

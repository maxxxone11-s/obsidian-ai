# Разделение ролей LLM и RAG

## Академическое определение

LLM хранит универсальные способы обработки информации в своих весах, тогда как RAG предоставляет модели внешние актуальные данные без изменения параметров.

## Инженерное назначение

Эта граница разделяет долговременные способности модели и часто обновляемые фактические знания.

LLM отвечает за языковое понимание, обобщение и рассуждение, а RAG отвечает за поиск релевантного внешнего контекста.

## Причина существования

Постоянно дообучать модель на каждой новой информации экономически и технически нецелесообразно.

RAG нужен, чтобы подключать новые документы и факты без изменения весов модели.

## Простое объяснение

LLM умеет рассуждать.

RAG приносит информацию, над которой нужно рассуждать.

## Как это работает

Типовая цепочка:

```text
user query
    ↓
embedding запроса
    ↓
поиск релевантных документов
    ↓
документы добавляются в context window
    ↓
LLM строит ответ
```

Веса модели при этом не меняются.

## Пример

Новость, появившаяся сегодня, может использоваться через RAG без переобучения весов модели.

Документ попадёт в контекст, а LLM применит свои обученные способности к этому документу.

## Типичные ошибки

- Считать, что RAG извлекает веса модели.
- Путать embedding документов с параметрами модели.
- Считать vector database памятью внутри Transformer.
- Думать, что добавление документа в RAG автоматически меняет знания модели.

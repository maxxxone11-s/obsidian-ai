# Context Window vs KV Cache

## Академическое определение

Context Window и KV Cache — независимые механизмы.

Контекстное окно формируется приложением и передается модели как входная последовательность. KV Cache существует только во время генерации одного ответа.

## Инженерное назначение

Эта концепция разделяет ответственность между приложением и Transformer.

Приложение отвечает за историю диалога и выбор сообщений, которые попадут в context window. Transformer во время generation использует KV Cache для ускорения вычислений внутри одного ответа.

## Причина существования

Transformer не хранит долгосрочную память между запросами.

Без явного разделения context window и KV Cache легко ошибочно считать, что модель сама помнит историю чата между API-вызовами.

## Простое объяснение

Историю чата хранит приложение.

Transformer каждый раз получает всю нужную историю заново. KV Cache создается во время генерации ответа и после завершения генерации удаляется.

## Как это работает

Новый запрос:

```text
История сообщений
+
Новое сообщение
↓
полностью отправляются в модель
```

Во время генерации создается KV Cache.

После завершения генерации KV Cache удаляется.

## Пример

Пользователь пишет второй вопрос.

Приложение повторно отправляет предыдущий диалог. Transformer строит новые Embedding, Q, K и V для входной последовательности, а затем использует KV Cache только во время генерации текущего ответа.

## Типичные ошибки

- Считать KV Cache памятью ChatGPT.
- Считать, что Transformer хранит историю между API-вызовами.
- Переносить инженерные решения Agent Memory на внутреннюю архитектуру Transformer.

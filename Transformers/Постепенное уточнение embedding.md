# Постепенное уточнение embedding

Область: [[Transformers/Transformers|Transformers]]

## Академическое определение

Постепенное уточнение embedding — процесс, при котором каждый [[Transformer Block]] получает контекстный embedding предыдущего блока и строит его более информативное представление.

Между блоками передаются только обновленные embedding, а не внутренние структуры Attention.

Архитектуру Transformer также можно рассматривать как последовательность переходов между специализированными пространствами представлений.

## Инженерное назначение

Эта архитектурная схема позволяет модели постепенно формировать все более сложные и абстрактные признаки.

В глубоком Transformer каждый блок выполняет небольшой шаг обработки, а не пытается сразу построить финальное представление токена.

Так одни и те же данные принимают формы, удобные для разных вычислительных задач: поиска, сопоставления, передачи информации, MLP-обработки и выбора следующего токена.

Независимые веса каждого [[Transformer Block]] позволяют разным слоям изучать разные уровни представления данных.

## Причина существования

Один большой блок плохо обучается и вынужден сразу решить слишком сложную задачу.

Последовательность одинаковых блоков позволяет постепенно уточнять представление токена и распределять сложную обработку между слоями.

Одно универсальное представление не подходит одновременно для поиска, передачи информации, построения признаков и выбора следующего токена.

Использование общих весов во всех blocks ограничило бы способность модели постепенно усложнять представление признаков.

## Простое объяснение

Каждый Transformer Block делает небольшой шаг к более точному пониманию токена в контексте.

Модель не хранит множество независимых embedding, а многократно преобразует текущее представление данных.

## Как это работает

```text
Embedding Layer
    ↓
Block1
    ↓
Context Embedding 1
    ↓
Block2
    ↓
Context Embedding 2
    ↓
...
```

Между блоками не передаются Query, Key, Value или веса Attention. Они существуют только внутри конкретного Transformer Block.

Если смотреть шире, embedding проходит цепочку пространств:

```text
Token IDs
    ↓
Token Embedding
    ↓
Query / Key / Value Space
    ↓
Attention Output
    ↓
MLP Output
    ↓
Vocabulary Logits
```

## Пример

```text
Block1 определил общий контекст.
Block2 уточнил смысл.
Block3 выделил более сложные зависимости.
```

Token `bank` после каждого блока становится все более похожим на представление `bank(finance)` либо `bank(river)` в зависимости от окружающего контекста.

Один embedding проходит через множество Linear-слоев, каждый раз приобретая новую семантическую роль.

При этом `Block1`, `Block2` и `Block3` имеют одинаковый код, но разные обучаемые параметры.

## Типичные ошибки

- Считать, что между блоками передаются Q, K и V.
- Считать, что каждый блок имеет заранее заданную роль.
- Считать, что один большой блок эквивалентен множеству последовательных блоков.
- Считать каждый Attention полностью независимым.
- Считать каждый новый embedding независимым объектом.
- Воспринимать Linear только как математическую операцию, а не как переход между пространствами представлений.
- Путать одинаковую архитектуру blocks с одинаковыми параметрами.
- Считать, что постепенное уточнение происходит одним и тем же набором весов.

# Параметр M в HNSW

Область: [[Vector Databases/Vector Databases|Vector Databases]]

## Академическое определение

`M` — максимальное количество соседних узлов, связи с которыми может хранить один embedding в графе HNSW на данном уровне.

## Инженерное назначение

Параметр управляет плотностью графа, расходом памяти и количеством альтернативных маршрутов во время поиска.

## Причина существования

Количество связей необходимо ограничивать, чтобы граф не превратился в дорогой полный граф, но связей должно быть достаточно для эффективной навигации и высокого Recall.

## Простое объяснение

`M` определяет, сколько «друзей» может иметь каждый embedding.

## Как это работает

При построении индекса каждому embedding сохраняется не более `M` соседей.

Маленькое `M`:

- требует меньше памяти;
- ускоряет построение;
- даёт меньше альтернативных маршрутов;
- может снижать Recall.

Большое `M`:

- требует больше памяти;
- замедляет построение;
- создаёт больше альтернативных маршрутов;
- обычно повышает Recall.

В большинстве реализаций одно значение `M` используется для всех уровней. Верхние уровни разрежены из-за меньшего количества embeddings, а не из-за обязательного отдельного значения `M`.

## Пример

При `M = 2` узел имеет очень мало направлений продолжения поиска. При `M = 16` тот же узел может быть связан с FastAPI, Django, Flask, Redis, PostgreSQL и другими соседями, что создаёт дополнительные маршруты.

## Типичные ошибки

- Считать, что увеличение `M` автоматически ускоряет поиск.
- Путать количество сохранённых связей с количеством узлов, исследуемых при запросе.
- Считать разное значение `M` на каждом уровне обязательным правилом HNSW.

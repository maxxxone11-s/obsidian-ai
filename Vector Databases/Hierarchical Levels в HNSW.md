# Hierarchical Levels в HNSW

## Академическое определение

HNSW организует граф в несколько уровней. Верхние уровни содержат небольшую часть embeddings и используются для быстрых переходов между крупными областями пространства. Level 0 содержит все embeddings и служит для детального поиска.

## Инженерное назначение

Иерархия существенно уменьшает количество переходов по графу при поиске в больших базах данных.

## Причина существования

Навигация только по одному плоскому графу даже при использовании ANN может потребовать слишком много коротких переходов. Верхние уровни дают возможность быстрее попасть в нужную область.

## Простое объяснение

Сначала алгоритм движется по редкой карте с крупными переходами, а затем спускается на более подробные карты и уточняет результат.

## Как это работает

1. Поиск начинается с верхнего доступного уровня и Entry Point.
2. Выполняются крупные переходы по небольшому числу узлов.
3. После достижения подходящей области поиск спускается на уровень ниже.
4. На Level 0 выполняется наиболее детальная навигация.

Каждый embedding получает случайный максимальный уровень и присутствует на нём и на всех уровнях ниже.

## Пример

Если embedding получил максимальный уровень 2, он присутствует на Level 2, Level 1 и Level 0, но отсутствует на более высоких уровнях.

## Типичные ошибки

- Считать, что каждый уровень содержит все embeddings.
- Думать, что уровни являются полными копиями базы.
- Считать, что верхний уровень просматривается полным перебором.
- Начинать мысленную модель поиска сразу с нижнего уровня.

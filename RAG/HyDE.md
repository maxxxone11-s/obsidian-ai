# HyDE

Область: [[RAG/RAG|RAG]]

## Академическое определение

HyDE — техника Query Transformation, в которой LLM генерирует гипотетический документ по вопросу пользователя, после чего embedding для retrieval строится по этому документу, а не по короткому исходному запросу.

## Инженерное назначение

HyDE создаёт более насыщенное семантическое представление запроса и помогает находить документы для коротких или неоднозначных вопросов.

## Причина существования

Короткий вопрос может содержать слишком мало признаков для качественного query embedding. Текст, похожий по форме на целевой документ, даёт embedding-модели больше тематического контекста.

## Простое объяснение

Система сначала пишет пример идеального документа по теме вопроса, а затем ищет реальные документы, похожие на этот пример.

## Как это работает

1. Пользователь задаёт вопрос.
2. LLM генерирует гипотетический документ по теме.
3. Embedding-модель строит vector гипотетического документа.
4. [[RAG/Retrieval|Retriever]] ищет похожие реальные chunks.
5. Гипотетический документ используется только для поиска, а не как финальный ответ.

## Пример

Для запроса «FastAPI» LLM создаёт краткое описание с ASGI, REST API, Pydantic, маршрутизацией и асинхронностью. По embedding этого описания система ищет реальные документы.

## Типичные ошибки

- Использовать гипотетический документ как ответ пользователю.
- Считать небольшую фактическую ошибку автоматической причиной полной бесполезности HyDE для semantic retrieval.
- Путать HyDE с добавлением списка терминов в [[RAG/Query Expansion|Query Expansion]].
- Не учитывать стоимость дополнительного вызова LLM.

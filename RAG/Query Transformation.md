# Query Transformation

## Академическое определение

Query Transformation — этап предварительной обработки пользовательского запроса, который изменяет его форму без изменения исходного намерения перед построением embedding и retrieval.

## Инженерное назначение

Этап формирует более подходящий поисковый запрос: разрешает местоимения, раскрывает сокращения, добавляет необходимый контекст и уменьшает влияние разговорной формулировки на retrieval.

## Причина существования

Пользовательский вопрос оптимизирован для общения, а не для поиска. Неясные ссылки, короткие формулировки и недостаток контекста могут привести к слабому query embedding и нерелевантным результатам.

## Простое объяснение

Query Transformation делает вопрос понятнее для поиска, сохраняя то, что пользователь действительно хотел узнать.

## Как это работает

1. Получает исходный User Question.
2. Анализирует контекст диалога и неясные части формулировки.
3. Создаёт улучшенный поисковый запрос без изменения намерения.
4. Для преобразованного запроса вычисляется embedding.
5. [[RAG/Retrieval|Retriever]] выполняет поиск по новому представлению.

## Пример

Вопрос «Как его установить?» при известной теме диалога преобразуется в «Как установить PostgreSQL?», после чего для уточнённого запроса строится embedding.

## Типичные ошибки

- Выполнять Query Transformation после построения embedding.
- Изменять смысл или добавлять неподтверждённое намерение пользователя.
- Путать улучшение поискового запроса с генерацией финального ответа.
- Применять transformation без оценки его влияния на retrieval.

# Top-K Retrieval

## Академическое определение

Top-K Retrieval — стратегия выбора фиксированного количества `K` кандидатов с наивысшими оценками релевантности после retrieval.

## Инженерное назначение

Top-K ограничивает объём контекста для последующих этапов, снижая шум, задержку и стоимость генерации.

## Причина существования

Поиск может вернуть множество кандидатов, но передавать их все reranker или LLM дорого и часто вредно для качества ответа.

## Простое объяснение

После сортировки система берёт только первые `K` результатов — например, пять наиболее похожих chunks.

## Как это работает

1. [[RAG/Retrieval|Retrieval]] вычисляет scores кандидатов.
2. Кандидаты сортируются по убыванию релевантности.
3. Выбираются первые `K` chunks.
4. Они передаются [[RAG/Reranking|reranker]] или непосредственно LLM.

## Пример

Система находит сотни потенциально релевантных chunks, но при `K = 5` передаёт следующему этапу только пять лучших.

## Типичные ошибки

- Предполагать, что увеличение `K` всегда улучшает ответ.
- Игнорировать шум и расход Context Window при большом `K`.
- Подбирать `K` без evaluation на реальных запросах.

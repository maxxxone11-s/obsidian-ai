# Reranking

## Академическое определение

Reranking — этап повторной оценки найденных документов, на котором более точная модель анализирует соответствие пары «запрос + документ» и перестраивает порядок кандидатов.

## Инженерное назначение

Reranking повышает точность финального контекста после быстрого retrieval, оставляя наиболее полезные для конкретного вопроса chunks.

## Причина существования

Высокое векторное сходство не гарантирует, что документ непосредственно отвечает на вопрос. Быстрый retriever оптимизирован для широкого отбора кандидатов, а не для глубокой оценки каждой пары.

## Простое объяснение

Retriever быстро находит возможные ответы, а reranker внимательнее перечитывает кандидатов и поднимает самые полезные выше.

## Как это работает

1. [[RAG/Retrieval|Retriever]] возвращает Top-K кандидатов.
2. Reranker оценивает каждую пару «question + chunk».
3. Кандидаты сортируются по новым scores.
4. В LLM передаются первые `N` документов, где `N ≤ K`.

## Пример

Для запроса «Как установить PostgreSQL?» retrieval может найти статьи об истории, архитектуре и установке PostgreSQL. Reranker поднимет инструкцию по установке выше остальных.

## Типичные ошибки

- Считать reranker заменой retriever.
- Запускать дорогой reranker на всей базе документов.
- Путать семантическое сходство с полезностью документа для вопроса.
